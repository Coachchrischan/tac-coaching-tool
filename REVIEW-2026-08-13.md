## Must fix (ACTIONED 2026-08-13)

### #1 [critical] Any read or parse error silently overwrites a doc with the seed
- Area: src/server/storagePlugin.ts (loadDoc)
- Suggestion: Seed only when the error code is ENOENT. On any other failure rename the file to <docId>.json.corrupt-<timestamp>, never overwrite it, and return 500 so the UI shows a save failure.
- Evidence: storagePlugin.ts:38-50: `try { return JSON.parse(readFileSync(...)) } catch { const env = { data: seeds[docId](), rev: 1, ... }; writeDoc(root, docId, env); return env; }` conflates ENOENT with unreadable/unparseable, and loadDoc is also called on the PUT path (line 111).

### #6 [critical] A failed save permanently clears the dirty flag, converting one blip into silent loss
- Area: src/lib/useDoc.ts (flush)
- Suggestion: Restore dirtyRef to true in the catch for non-conflict errors and schedule a backoff retry; add a Retry button to SaveBadge's error state wired to flush.
- Evidence: useDoc.ts:75 sets `dirtyRef.current = false;` before `store.save(...)`; the catch only does `setSaveState('error')` and SaveBadge renders a bare label with no retry.

### #10 [high] Tabbing through a filled exercise field silently rewrites it with the top fuzzy match
- Area: src/components/Combobox.tsx
- Suggestion: Track a dirty flag set in onChange and cleared on focus/commit; only commit from the dropdown on Tab or Enter when dirty, never on Shift+Tab, and optionally keep the list closed until the first keystroke.
- Evidence: Combobox.tsx:82 `onFocus={() => text && setOpen(true)}` reopens the list with the stored name as the query, and lines 57-63 commit the highlighted result on any Tab, with no Shift+Tab check and no test that the user typed since focus.

### #8 [high] Fixed Lower/Upper/Full session tuple cannot hold ESD or Hyrox, the club's dominant class types
- Area: src/types/documents.ts (ProgramWeek, SessionFocus), src/seed/index.ts, src/tabs/programming/ProgrammingTab.tsx
- Suggestion: Make ProgramWeek.sessions a variable-length array with editable focus/name, widen SessionFocus to include 'esd' and 'hyrox', and add add/remove-session controls with matching FOCUS_TITLE entries in ProgrammingTab, TvPage and blurb.ts.
- Evidence: documents.ts:95 `sessions: [Session, Session, Session]; // Lower, Upper, Full Body` and SessionFocus = 'lower' | 'upper' | 'full', while the seeded timetable has 8 ESD and 3 Hyrox blocks per week versus 6 strength blocks, and no Full Body class type at all.

- Evidence: useDoc.ts:64-69 cleanup fires `flushPending(false)` fire-and-forget while the next tab's mount immediately runs `store.load(id)`; nothing orders the two, and 'program' and 'library-overrides' are each mounted from multiple tabs despite the documents.ts isolation claim.
